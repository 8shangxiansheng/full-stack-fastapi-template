# 苍穹外卖后续增强路线图

更新时间：2026-03-16

## 当前基线

- 已完成 `ISS-20260303-001` 到 `ISS-20260303-023`
- 当前能力已覆盖：
  - 菜单、购物车、地址、订单、支付、履约后台
  - OpenAPI SDK、Playwright、压测基线、统一门禁、默认密钥治理

## 下一阶段目标

- 从“可上线 MVP”推进到“可运营、可观测、可灰度、可持续扩展”

## Phase 5：发布与运行稳定性

### ISS-20260316-024 灰度发布与回滚脚本化

- 目标：将 staging / production 的部署检查、灰度发布、回滚流程标准化
- 交付：
  - 发布步骤脚本
  - 回滚步骤脚本
  - 灰度检查清单
  - 关键链路 smoke 脚本
- 优先级：P0

### ISS-20260316-025 运行时监控与告警

- 目标：补齐订单、支付、错误率和资源使用的可观测性
- 交付：
  - 核心业务指标定义
  - 应用日志 / 结构化日志策略
  - 监控面板字段约定
  - 告警阈值建议
- 优先级：P0

## Phase 6：结算与库存域增强

### ISS-20260316-026 优惠券 / 满减 / 配送费结算域

- 目标：扩展订单金额模型，使业务从单一商品金额走向真实结算
- 交付：
  - 优惠券模型与校验
  - 满减规则
  - 配送费规则
  - 订单结算明细响应
- 优先级：P1

### ISS-20260316-027 库存预占与超卖保护增强

- 目标：增强高并发下的库存一致性和补偿能力
- 交付：
  - 库存预占 / 释放策略
  - 订单取消 / 退款补偿
  - 库存异常巡检与后台管理
- 优先级：P1

## Phase 7：运营与配送增强

### ISS-20260316-028 后台订单筛选、搜索、统计看板

- 目标：提升运营后台的订单处理效率
- 交付：
  - 多条件筛选
  - 退款单 / 异常单视图
  - 时间范围统计
  - 聚合看板增强
- 优先级：P1

### ISS-20260316-029 地址与配送规则增强

- 目标：让地址能力从“能下单”进化为“能配送”
- 交付：
  - 配送范围限制
  - 地址标签与备注
  - 配送时段能力
  - 地址合法性校验增强
- 优先级：P1

## Phase 8：前端与工程深化

### ISS-20260316-030 前端首屏与大包优化

- 目标：降低当前前端大 chunk 风险，优化首屏加载体验
- 交付：
  - 路由级拆包
  - 懒加载策略
  - Dashboard 与 Orders 页面包体优化
- 优先级：P2

### ISS-20260316-031 测试金字塔补强

- 目标：从“主链路测试齐全”提升到“分层测试稳定”
- 交付：
  - 服务层测试补齐
  - Contract 测试
  - CI 中 `fast` / `full` 门禁分层执行建议
- 优先级：P2

## 为什么这样排

- 先补“发布、回滚、监控”，因为这决定系统是否能稳定进入真实运行期
- 再补“结算、库存”，因为这决定业务模型是否接近真实外卖场景
- 最后补“运营体验、前端性能、测试深化”，因为这些收益大但不阻塞当前可运营性
